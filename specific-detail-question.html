Giải thích chi tiết cơ chế Dependency Injection và Inversion of Control (IoC) trong Spring Boot 3

Nguyễn Văn Nam UNETI_USER star 150 điểm uy tín
schedule 10/09/2026, 14:30 visibility 428 lần xem
Java Spring Boot Backend CNTT-K16

Em đang làm bài tập lớn môn Lập trình Web nâng cao bằng Spring Boot. Khi khai báo các Service và Repository, em thấy có 3 cách tiêm phụ thuộc phổ biến: Field Injection (gắn @Autowired trực tiếp trên biến), Setter Injection, và Constructor Injection.

Thầy giáo bộ môn khuyến nghị cả lớp nên dùng Constructor Injection và gắn từ khóa final, nhưng em chưa thực sự hiểu bản chất tại sao lại vượt trội hơn hẳn so với việc chỉ đặt annotation ngắn gọn như sau:

StudentService.java 
@Service
public class StudentService {
    
    // Bắt buộc immutability
    private final StudentRepository studentRepository;

    // Constructor Injection tự động (Spring Framework 4.3+)
    public StudentService(StudentRepository studentRepository) {
        this.studentRepository = studentRepository;
    }
    
    public List<Student> getAllEnrolled() {
        return studentRepository.findAllActive();
    }
}
info Lưu ý học thuật: UNETI Syllabus K16

Theo chuẩn đồ án tốt nghiệp khoa Công nghệ thông tin UNETI, việc tuân thủ nguyên lý SOLID (đặc biệt là Dependency Inversion Principle - DIP) là tiêu chí chấm điểm kiến trúc phần mềm bắt buộc trong học phần Công nghệ phần mềm & Lập trình Web nâng cao.

Chào em Nam, đây là câu hỏi cốt lõi và rất hay xuất hiện trong phỏng vấn tuyển dụng Java/Spring developer cũng như bảo vệ đồ án.

Thầy giải thích ngắn gọn bản chất IoC (Inversion of Control) là nguyên lý đảo ngược quyền kiểm soát: thay vì class tự khởi tạo đối tượng phụ thuộc bằng từ khóa new, quyền này được bàn giao hoàn toàn cho Spring IoC Container. Dependency Injection (DI) chính là phương thức hiện thực hóa nguyên lý này.

Lý do tại sao Constructor Injection luôn được khuyên dùng tuyệt đối:

  • Immutability (Bất biến): Cho phép khai báo biến với từ khóa final, đảm bảo dependency không bị gán lại sau khi khởi tạo.
  • Dễ Unit Test: Khi viết Mockito test, em có thể khởi tạo class và truyền mock repository qua constructor bình thường mà không cần khởi động Spring Context hay dùng Reflection hack.
  • Phát hiện sớm Circular Dependency (Phụ thuộc vòng): Spring sẽ ném exception BeanCurrentlyInCreationException ngay lúc ứng dụng startup thay vì lỗi âm thầm khi runtime.

Mình bổ sung thêm kinh nghiệm thực chiến từ đồ án kỳ trước: Khi dùng Field Injection (@Autowired private PaymentRepo paymentRepo;), đến lúc viết Unit Test JUnit 5 nếu bạn quên không dùng Runner của Spring thì object Repo luôn bị NullPointerException.

Với Constructor Injection, bạn chỉ cần gọi new PaymentService(mockPaymentRepo) là test chạy ngon lành trong 10 mili-giây mà không tốn cả chục giây nạp toàn bộ Spring Container lên. Rất nên tạo thói quen này từ sớm nhé bạn!
